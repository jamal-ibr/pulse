# Daily digest pipeline

A scheduled pipeline that gathers the last 24 hours of source material (72
hours on Mondays), filters it against the uses defined in the reader profile,
and emails a single plain-text digest readable on a phone in under seven
minutes.

## Privacy model (this repo is public)

Nothing personal lives in the repository, and digest content only ever
travels by email:

- The recipient address, reader context, "plate" list and masthead live in
  the `DIGEST_PROFILE` secret (shape in `profile.example.yaml`; local runs
  use the gitignored `digest/profile.local.yaml`).
- Actions run logs are world-readable on public repos, so CI never prints
  digest content. Dry runs and backfills in CI are emailed instead, with a
  `[dry-run]` or `[backfill]` subject prefix.
- Nothing content-bearing is committed. The only files the workflow commits
  are `data/seen-cache.json` (URLs and title tokens of public news) and
  `data/feedback.jsonl` (lane/source IDs and your ratings, no headlines).
- Weekly tuning proposals are emailed, never committed or logged.
- Local runs write digests to `/archive` and proposals to `proposals/`,
  both gitignored.

```
GitHub Actions (06:00 Europe/London)
  └─ Node/TypeScript
       ├─ FETCH       verified RSS feeds (sources.yaml) + Anthropic web_search for feed-less topics
       ├─ DEDUPE      URL + fuzzy title match against a 14-day seen cache (data/seen-cache.json)
       ├─ TRIAGE      Claude Haiku 4.5, 20 items per call, score 0-5, discard below 3
       ├─ SYNTHESISE  Claude Sonnet 5 returns structured JSON; a deterministic
       │              renderer produces the email, so every link comes from a
       │              fetched, link-checked item and the format never drifts
       └─ DELIVER     email via Resend
```

## Setup

1. Add three repository secrets (Settings, Secrets and variables, Actions):
   - `ANTHROPIC_API_KEY`: from console.anthropic.com. Note this is separate
     from a Claude Pro/Max subscription; the API is pay-as-you-go and needs
     its own credit balance.
   - `RESEND_API_KEY`: from resend.com. The default onboarding sender only
     delivers to the email your Resend account is registered under; verify a
     domain and change `sender` in `config.yaml` to send elsewhere.
   - `DIGEST_PROFILE`: your personal profile YAML. Copy
     `profile.example.yaml`, fill it in, paste the whole file as the secret
     value.
2. The cron only fires on the default branch. Merge this branch to `main` to
   switch the schedule on. `workflow_dispatch` works from any branch first.

## Commands

```
npm run digest -- --dry-run       # full pipeline; prints locally, emails [dry-run] in CI
npm run digest -- --backfill 7    # one digest per day for the last 7 days
npm run digest -- --no-search     # feeds only, skip web_search
npm run digest -- --fetch-only    # fetch + dedupe counts only, no secrets needed
npm run rate -- useful            # log a rating for today (useful | thin | off-target)
npm run rate -- 2026-07-13 thin   # log a rating for a past digest
npm run tune                      # summarise last 7 days, propose (not apply) edits
npm test                          # unit tests
```

From the repo root, `npm run digest -- --dry-run` proxies into this workspace.

## Sources

`sources.yaml` groups feeds and search topics by lane. Every feed URL in it
was fetched and verified from the Actions runner; the verification report
lives at `data/feed-verification.json` and can be regenerated by pushing a
change to `scripts/verify-feeds.mjs` (the "Digest: verify feeds" workflow).
Sources with no working feed are covered by `search_topics` through the
Anthropic `web_search` tool, capped per lane in `config.yaml` to keep cost
predictable.

## Cost

Printed at the end of every run and alarmed above the `budget.run_alert_gbp`
threshold (default 15p). Model routing keeps it low: Haiku 4.5 for triage and
search, Sonnet 5 for the one synthesis call, prompt caching on the shared
context block. Prices live in `config.yaml`, not code.

## Feedback loop

Each digest ends with three `mailto:` rating links (useful, thin,
off-target). The sent-item stats (lane and source only) are appended to
`data/feedback.jsonl` automatically at send time; log your rating with
`npm run rate -- useful`. Every Sunday the tune workflow reads the week's
ratings plus those stats and emails a proposal suggesting triage prompt and
sources.yaml edits. It proposes; you approve and apply.

## Failure behaviour

The run script catches errors and emails them via Resend. If the run dies
before it can do that (dependency install, checkout), the workflow's
`if: failure()` step sends a fallback email, reading the recipient from the
`DIGEST_PROFILE` secret. An empty or slow news day is not a failure: the
digest sends fewer items, and if nothing earns its place it sends nothing
and says so in the log.
